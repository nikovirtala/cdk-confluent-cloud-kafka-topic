# Project Structure

## Source Code (`src/`)

- **index.ts**: Main CDK construct export (`ConfluentKafkaTopic`)
- **confluent-topic-handler.lambda.ts**: Lambda handler source for custom resource
- **confluent-topic-handler-function.ts**: Lambda function construct wrapper

## Compiled Output (`lib/`)

TypeScript compilation output matching `src/` structure. Generated by `tsc` with JSII metadata.

## Lambda Assets (`assets/`)

- **confluent-topic-handler.lambda/**: Bundled Lambda function code
  - **index.js**: esbuild-bundled handler with dependencies

## Tests (`test/`)

- **index.test.ts**: Vitest unit tests using CDK assertions
- Tests verify CloudFormation template synthesis and resource properties

## Scripts (`scripts/`)

- **generate-topic-config-types.ts**: Generates TypeScript types from Confluent Cloud documentation
- Runs automatically during pre-compile phase

## Documentation (`docs/`)

- **topic-config-reference.md**: Auto-generated Confluent topic configuration reference (gitignored)

## Generated Files

- **API.md**: JSII-generated API documentation
- **lib/generated/**: Auto-generated TypeScript types for topic configuration
- **dist/**: JSII multi-language package output

## Configuration Files

- **.projenrc.ts**: Projen project definition (source of truth for config)
- **tsconfig.json**: TypeScript compiler configuration
- **tsconfig.dev.json**: Development-specific TypeScript config
- **vitest.config.ts**: Test configuration
- **biome.jsonc**: Code formatting and linting rules

## Key Patterns

- Projen manages most configuration files (marked with "Generated by projen" comment)
- Lambda functions are bundled separately with esbuild
- Type generation happens before compilation to ensure consistency
- JSII enables multi-language support (Python, Java, C#, Go)
